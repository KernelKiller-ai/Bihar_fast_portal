# BiharFast Quiz / Mock-Test Audit

## Summary

The quiz is a React single-page experience backed by FastAPI and Supabase: the browser lists active quiz slots, fetches questions without answer keys, and submits answer choices for server-side scoring against `master_answer_keys`. The most important verified issues are that anonymous demo submissions return answer keys without verifying that the caller actually took the demo (or that the quiz is active), demo answers can fail because the browser shuffles questions while the server grades the first five in stored order, client-supplied elapsed time controls leaderboard tie-breaking, and several database errors are rendered as empty/success-shaped results. Public quiz reads do not select answer keys. Live database policies, RPC deployment, proxy topology, and actual mobile rendering cannot be established from this repository.

```mermaid
    I -- Full --> J[Require signed-in user; start browser timer]
    I -- Demo --> K[No login; show five shuffled questions]
    J --> L[POST /api/quiz/submit with quiz_id, answers, identity fields, elapsed time]
    K --> L
    L --> M[FastAPI validates identity/quota and loads questions]
    M --> N[Load answer keys via service client; calculate score server-side]
    N --> O[Return score and per-question correct answer/explanation]
    O --> P[Show scorecard and solutions]
    P --> Q[Full attempts saved to browser localStorage; demo can be saved locally]
    P --> R[Leaderboard UI queries Supabase directly]
    S[GET /api/quiz/leaderboard/{quiz_id}] -. separate backend endpoint .-> T[Returns public leaderboard projection; UI does not call it]
```

The answer key is therefore server-side for the normal question-fetch flow; it is returned only in the submit result.
